# Investor change history — design

Agreed with the owner 2026-09-28. Input to `/10x-plan investor-change-history`. Linear: EX-881.

## Goal

The investor can **check for themselves what changed** in their kosztorys and when — scope, prices and
progress — instead of trusting the owner's word. Today the investor view is live-only: nothing the
client saw yesterday is recoverable from their side.

## Starting point in code (already exists)

- `kosztorys_snapshots` (`src/lib/db/snapshots.ts`) — raw table, payload = tree (sections / items /
  stages / progress) + three settings (`wToolsCoeff`, `ownToolsCoeff`, `vatRate`). Measured on the local
  dump: 13 kB average, 24 kB max per payload (TOASTed).
- Auto capture (`use-auto-snapshot.ts`) runs **only while the editor is open**, every 10 min, gated on
  the undo revision. Named manual versions via „Zapisz jako…".
- Retention (`gcSnapshots`, daily `cleanup` cron): all for 30 days → newest per day to 120 → newest per
  week to 365 → deleted. Manual versions exempt from the bands, not from the 365-day cutoff.
- Owner's „Wersje" drawer can only **restore** a version, not display one.
- Investor view: `/k/[token]` and „Podgląd dla inwestora" (`/podglad-inwestora/[id]`), both via
  `getPreviewKosztorys*` → `KosztorysEditorBody preview`, filtered by the investment's client-view
  settings.

## Decisions

| #   | Decision                                                                                                                                                                                                                                                                                                                                                                           | Why                                                                                                                                                                                                                                                                                    |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | The feature is **for the investor**, on their link; the owner sees the identical screen in „Podgląd dla inwestora".                                                                                                                                                                                                                                                                | Purpose is client-side verification; the owner's preview must stay byte-identical to what the client gets.                                                                                                                                                                             |
| 2   | **One version per day** — the kosztorys as it stood at the end of that day (Europe/Warsaw). **Named manual versions** („Zapisz jako…") are stored alongside and appear as **their own entries**, with their label, as milestones — even on a day that also has an end-of-day entry.                                                                                                | 10-min auto versions are noise and expose half-edited states; owner-curated-only versions would let the owner choose what the client may verify.                                                                                                                                       |
| 3   | **Progress counts as a change** (Pomiar per etap), alongside scope/price (pozycje added/removed, Przedmiar, Cena j.m., rabat).                                                                                                                                                                                                                                                     | Owner: "obviously".                                                                                                                                                                                                                                                                    |
| 4   | **A list of days on which something changed**, newest first. Each entry counts its differences **from the current version** („2 różnice względem bieżącej"). Days whose version equals the previous one are not listed. _(Amended at `7eee889e`: originally a per-day summary vs the previous listed day — replaced so the list and the version view make the same comparison.)_   | Tells the investor which day is worth opening. _(Assumption stated to the owner, not explicitly confirmed — revisit if it reads wrong.)_                                                                                                                                               |
| 5   | **Opening a day compares that day's version with the CURRENT (live) version** — "what has changed since then". No "od" picker. Added pozycje marked, removed ones struck through, changed values shown old → new.                                                                                                                                                                  | Owner's correction. An investor checking in monthly opens the day of their last visit.                                                                                                                                                                                                 |
| 6   | **Scope = the kosztorys only** (rozpiska, Przedmiar, Pomiar per etap, Cena j.m., wartości, rabat). The money block (Wpłaty, materiały, Do zapłaty) stays live-only.                                                                                                                                                                                                                | Transfers carry their own dates and the investor already sees them listed; no second history to build.                                                                                                                                                                                 |
| 7   | **Columns/rows follow the investor's CURRENT client-view settings** for every past day.                                                                                                                                                                                                                                                                                            | Presentation, not a figure — and a column hidden today must not reappear through history.                                                                                                                                                                                              |
| 8   | **Record the global rabat** (`globalDiscountType` / `globalDiscountValue`) in every snapshot payload from now on. Restore still **ignores** it — restoring a version must not reset the live rabat (existing rule in `snapshot-format.ts`).                                                                                                                                        | Otherwise a past day's wartość netto is computed with today's rabat. Additive optional field → no `SNAPSHOT_SCHEMA_VERSION` bump.                                                                                                                                                      |
| 9   | Versions stored **before** #8 show pozycje and their values normally, but the total is marked **„rabat nieznany"** — never silently filled with today's rabat.                                                                                                                                                                                                                     | Scope and progress of those days are still true; only the rabat line is unknown. The field's absence in the payload IS the marker.                                                                                                                                                     |
| 10  | **Nightly end-of-day capture** (new `vercel.json` cron entry, not bolted onto `cleanup`): for every kosztorys whose tree changed since its last stored version, store one version server-side, independent of the editor being open.                                                                                                                                               | Editor-driven capture misses the last minutes before closing the editor; those edits would then land on a later day. The day an entry is dated must be the day the change was made.                                                                                                    |
| 11  | History before this change is built from the **existing record**: the newest 10-min version of each Warsaw day (daily or weekly depending on age, because of past thinning). **Old rules for old rows** (owner, /10x-plan): past rows are not reclassified — past „Zapisz jako…" versions are not milestones, and past 10-min rows keep thinning and expiring under today's bands. | Owner: "we are already storing it".                                                                                                                                                                                                                                                    |
| 12  | **Retention of investor-visible versions — end-of-day AND named ones written after ship:** never thinned or deleted while the investment is **Planowana or Aktywna**; after **Zakończona**, kept **one more year**, then deleted. Reopening stops the clock. The 10-min versions and pre-ship manual ones keep today's rules.                                                      | Owner. Planowana counts as live — that is the negotiation phase, when offer changes matter most. Named versions are stored alongside the daily ones and are what the investor would most want to return to (e.g. „Oferta podpisana"); today they die at 365 days like everything else. |
| 13  | Record **when an investment was marked Zakończona** (new nullable completion date: set on the transition to `completed`, cleared on reopening).                                                                                                                                                                                                                                    | Nothing records it today; "a year after completion" needs it. Migration — additive.                                                                                                                                                                                                    |
| 14  | **Matching pozycje between two versions:** by item id; where the id sets are disjoint (a restore or „wczytaj szablon" mints new ids — `restore-kosztorys.ts`), fall back to sekcja name + opis + j.m.                                                                                                                                                                              | Otherwise one restore makes the whole kosztorys read as "removed + added".                                                                                                                                                                                                             |
| 15  | The owner **cannot hide a day** from the investor's history.                                                                                                                                                                                                                                                                                                                       | Trust purpose (#1).                                                                                                                                                                                                                                                                    |

## Out of scope

- A history of the money block (Wpłaty / materiały / Do zapłaty) — #6.
- Comparing two arbitrary past days — #5 (always vs current).
- A preview in the owner's „Wersje" drawer — the owner uses „Podgląd dla inwestora".
- Any change to the 10-min auto capture or to restore behaviour.

## Open for /10x-plan

- Cron timing vs day attribution: cron runs in UTC; pick a slot and a rule so edits just after Warsaw
  midnight don't land on the previous day (and DST doesn't shift it).
- "Tree changed since last version" detection for the nightly job — payload hash vs row `updated_at`.
- How an end-of-day version is marked in `kosztorys_snapshots` (new `kind` vs derived "newest per day"),
  and how #12 plugs into `gcSnapshots` without weakening the existing bands for 10-min versions.
- Szablon / warsztat investments (`template_preset_id`) — excluded from the investor history.
- Routes: history list + day view under `/k/[token]/…` and `/podglad-inwestora/[id]/…`, both through the
  same token/auth gates as today.

## Tests (risk-anchored — extend `test-plan.md` via `/10x-test-plan` if not covered)

- Unit: the diff (incl. id-fallback matching, Pomiar per etap, rabat present/absent), the newest-per-day
  selection + "no-change day is not listed", the retention rule (#12, incl. reopen).
- DB (integration): the nightly capture stores only when the tree changed; rabat lands in the payload;
  restore still ignores it.
- E2E (one): investor opens the history via their link, opens a past day, sees a changed Przedmiar
  old → new.
